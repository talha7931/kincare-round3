# KinCare Round 3 — Submission Checklist

Official Round 3 requirements supplied by the team:

- [ ] Working prototype/MVP/PoC.
- [ ] Live demonstration or demonstration video, as instructed.
- [ ] Source code/repository link, where applicable.
- [ ] Brief technical documentation.
- [ ] Explanation of implemented features and limitations.
- [ ] Future development plans and potential improvements.

## Prototype and access

- [ ] Android APK built and tested on a real Android phone.
- [ ] PWA deployed over HTTPS and installable/tested on a target browser.
- [ ] Both clients connect to the same Supabase project.
- [ ] Same caregiver/profile data is visible in both clients after sync.
- [ ] Memory Deck photo/context/question/answer workflow works.
- [ ] Audio playback and verbal response recording work, or documented fallback is shown.
- [ ] Odd One Out works and records responses.
- [ ] Everyday Object Sorting works and records responses.
- [ ] Caregiver dashboard uses real stored records.
- [ ] Healthcare consultation PDF exports correctly and has non-clinical disclaimer.
- [ ] Offline workflows tested on both clients.
- [ ] Sync round-trip verified and duplicates checked.

## Source code and documentation

- [ ] GitHub repository URL is accessible to evaluators if requested.
- [ ] README setup instructions are tested on a clean machine or fresh checkout.
- [ ] Supabase migrations included; no secrets committed.
- [ ] Architecture and database docs match implementation.
- [ ] Offline/sync design and test evidence documented.
- [ ] Implemented features and known limitations document updated.
- [ ] Future scope separated from completed features.

## Demonstration

- [ ] 3–5 minute demo script prepared (duration is a recommendation, not an organiser requirement).
- [ ] Synthetic demo caregiver/profile and safe sample photos prepared.
- [ ] Both applications opened and ready before recording/live demo.
- [ ] Memory Deck upload and playback demonstrated.
- [ ] Both games demonstrated.
- [ ] Dashboard and PDF report demonstrated.
- [ ] Offline test and reconnection/sync demonstrated or recorded as a separate clip.
- [ ] Backup demo video saved in case live connectivity fails.

## Portal confirmation

- [ ] Confirm accepted upload format(s) and maximum file size.
- [ ] Confirm whether APK, PWA URL, ZIP/source repository, video or document is required.
- [ ] Confirm whether a live demo link is submitted now or presented later.
- [ ] Download the uploaded file(s) and verify they open.
- [ ] Confirm portal status shows Submitted.
